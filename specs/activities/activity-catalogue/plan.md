Use InnoDB, utf8mb4, current default table collation (configured utf8mb4_unicode_ci), explicit column override; do not change existing tables or collation configuration. Named DDL (logical equivalent, verify SHOW CREATE TABLE, metadata and enforcement on actual MySQL):

```sql
UNIQUE KEY uq_activities_name (name),
CONSTRAINT chk_activities_flags CHECK
  (supports_hourly IN (0,1) AND supports_subscription IN (0,1) AND is_active IN (0,1)),
CONSTRAINT chk_activities_billing CHECK
  (supports_hourly = 1 OR supports_subscription = 1),
CONSTRAINT chk_activities_hourly_rate CHECK
  ((supports_hourly = 1 AND hourly_rate IS NOT NULL AND hourly_rate > 0)
   OR (supports_hourly = 0 AND hourly_rate IS NULL)),
CONSTRAINT chk_activities_monthly_price CHECK
  ((supports_subscription = 1 AND monthly_price IS NOT NULL AND monthly_price > 0)
   OR (supports_subscription = 0 AND monthly_price IS NULL)),
CONSTRAINT chk_activities_name CHECK (CHAR_LENGTH(TRIM(name)) > 0)
```

Explicit IS NOT NULL avoids CHECK UNKNOWN loopholes; flags NOT NULL plus checks. DB TRIM guard covers empty/ordinary ASCII space names; application Unicode edge trim is stricter. MySQL DECIMAL can coerce/round invalid SQL input before checks, so the API lexical check is essential; do not claim SQL enforces JSON lexical form or rejects every excess-precision SQL write. Require actual CHECK enforcement (MySQL >=8.0.16), strict mode, UTC session and matching charset/collation. EXPLAIN ANALYZE needs compatible MySQL (8.0.18+ for measurement); inspect version/available collation on CI and eventually target host; do not assume MariaDB equivalent.

Preflight actual equality and LIKE behavior under explicit collation, plus actual unique-index inserts/updates on guarded disposable CI. Expected: Swimming/swimming equal; edge-trimmed duplicate equal; same Arabic name equal; Cafe/Café distinct; الرسم/الرَسم distinct; كرة قدم/كرة  قدم distinct. Check Arabic hamza/alef variants (ا/أ/إ/آ), ي/ى, ه/ة, Arabic vowel marks/tatweel, composed/decomposed accented Unicode, mixed scripts, nonbreaking/Unicode whitespace and supplementary characters. Record exact equality and LIKE differences, including canonical equivalence and NO PAD/trailing spaces; not assume SQL LIKE equals unique collation comparison. Preserve original trimmed spelling; no transliteration, folding, normalization or second generated name column. If real outcomes contradict approved expectations or reveal a material unapproved equivalence (e.g. distinct business names collide), stop for review; no automatic collation switch. Actual guarded fixture evidence is recorded in [tasks.md](tasks.md), CI 45899369824. MySQL 8.0.46 matched all explicitly approved equality expectations; tatweel and internal NBSP additionally compare equal and conflict with the unique index. Native LIKE differs from equality for tatweel and composed/decomposed acute accents. The explicit review gate failed as designed. These observations are not approval of the two newly discovered equivalences: the proposed retained collation and literal LIKE semantics need user review before affected implementation. No automatic fallback.

Initial indexes exactly PRIMARY(id), UNIQUE(name). Low-cardinality flags alone not justified; active selector may benefit from (is_active,name) only after EXPLAIN/observed measurements and review. Leading wildcard substring may scan rows or index; no claim of index seek. No redundant name index, fulltext, persisted mode or count.
