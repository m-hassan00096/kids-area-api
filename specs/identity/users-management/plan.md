## 3. Database and storage model

Propose one forward migration in Identity after F02 migrations: `users.avatar_key VARCHAR(40) CHARACTER SET ascii COLLATE ascii_bin NULL`, default NULL, hidden/internal. ## 5. Query design, pagination and Select Registry

### 5.1 Users table and detail

Read primary. Explicit index query over canonical User using Spatie QueryBuilder::for and three allowlisted filters (search, roleId, isActive). No client sort/include/fields; reject unknown top-level query and nested filters before construction; allow only page/perPage/filter. Index Form Request validates scalar shapes, search <=255 characters and outer trim, parse positive integer with bounds before DB, reject malformed/overflow; clamp valid perPage >100 to 100 without querying 200. Fixed users.id DESC, including inactive. Full count and page use identical filter predicates; one count, one page query, one bounded eager-load role query for page IDs (detail one record and role query). Select only public columns plus internal avatar key; email only detail, never hash/auth_version or raw model serialization. No per-row disk stat, no per-row role query; project avatarUrl/null from key. Eager-load native role memberships incl inactive, validate exact one matching guard; no arbitrary first on anomalies. If count/page/role coherence needs a single snapshot, use a short read-only consistent MySQL transaction on primary (verify isolation), no manager mutex or write locks. Out-of-range/empty pages return empty items and valid metadata. Respect existing authorized visibility.

Proposed illustrative query structure, not final code:

```sql
SELECT COUNT(*) FROM users
WHERE (name LIKE ? ESCAPE '!' OR username LIKE ? ESCAPE '!'
       OR phone LIKE ? ESCAPE '!')
  AND is_active = ?
  AND EXISTS (
    SELECT 1 FROM model_has_roles mr JOIN roles r ON r.id = mr.role_id
    WHERE mr.model_id = users.id AND mr.model_type = ?
      AND r.id = ? AND r.guard_name = 'web'
  );
-- Same predicate for selected page, ORDER BY users.id DESC LIMIT/OFFSET.
-- Load role/pivot for page IDs once; no one-to-many JOIN in paginated count.
```

Bind literal search pattern after replacing ! -> !!, % -> !%, _ -> !_ then wrap %; no string concatenation of user SQL. Existing username/phone ASCII/bin collation ensures case/leading-zero semantics (verify actual MySQL LIKE behavior, safe explicit collation if needed), name uses stored text collation; exact morph/guard checks consistent with IdentityAccess and index-friendly predicates. No LOWER(username), CAST(phone AS number), prefix or full-text change: contains search is not B-tree range-indexable. Avoid joining all permissions for list; no role grants in response. Role filter uses EXISTS, doesn't drop legitimate inactive assignments or inflate counts; valid unknown role -> empty. Use custom/allowed callback filters with normalized typed values captured from validated request, not blind Spatie default partial filter: actual [6.4.4 QueryBuilderRequest](https://github.com/spatie/laravel-query-builder/blob/6.4.4/src/QueryBuilderRequest.php) splits commas and converts literal true/false to booleans. Preserve literal search containing comma/true/false/0; avoid global static delimiter changes across requests. Callback closes over validated raw search; use package allowlist and dispatch with normalized request/validated value, test actual resolved version. Ensure false/0 filters apply. All user-facing payloads as approved spec, including userId and no createdAt. No Me changes.

Performance: target at most three domain SQL statements for nonempty page (count, page, role eager load), plus actual existing auth/session and permission queries counted separately; no N+1 across 15/100 rows. Explain and measure unfiltered, search Arabic/username/phone, role/status combinations at synthetic 100/1,000/10,000 retained Users (stress scenario, not capacity promise). Measure counts, examined rows, wall times and pagination offset behavior; no new search/status index absent demonstrated need and reviewed justification. No external search engine. Avatar delivery uses independent bounded fetch requests (not embedding bytes in list); lazy frontend fetch/caching behavior outside backend scope, benchmark avatar IO separate; no 100-image eager server-side processing.

## 6. Transactions, RBAC and session revocation

Reuse permanent manager row mutex and existing `IdentityAccessMutation`; extend minimally, no new lock/sentinel. Current execute owns transaction and verifies actor permission via currentHasAll and permanent roles/six-capability postcondition, but does **not** lock/check initiating session. Its finally cache clear occurs after transaction and could fail after commit; distinguish commit outcome explicitly before file cleanup or returning error. Keep F01 callers/tests compatible. Reuse shared lock order established with F02. Normal reads never acquire manager mutex.

Proposed mutation order:
1. Fresh middleware admission and capability; validate input, check obvious target rules, perform Argon2id hash and image validation/staging outside global mutex and transaction (avoid slow file/hash while holding locks). Do not hold DB lock while decoding/file streaming. Bind candidate key to this attempt only. Staging has no authoritative DB reference.
2. Ensure no ambient transaction. Use one InnoDB outer DB transaction (attempts=1, no blind retry on commit ambiguity). Acquire permanent manager role mutex, run currentHasAll(permission, actorId) using current ordered roles/users/pivots/definitions/grants reads; lock/re-read target state and actual current actor row, check founder existence/ID 1 for create, target protection/self-delete/self-reset, current target role membership incl inactive rows and direct-grant anomalies. Lock necessary target role/pivot rows in same serialized scope; no reverse acquisition of limiter locks. Reuse existing currentHasAll conservative small staff catalogue locks (R09 monitoring).
3. Lock actual initiating session row by original request ID after current access rows, compare owner, admitted/current version, user auth_version, active/eligible actor and idle cutoff now > last_activity+43200 boundary (valid exactly when last_activity > now-43200). Missing/expired/revoked -> 401, current permission/eligibility denied -> 403; retire invalid session only after rollback/outside transaction, never retire a still-valid session merely for absent permission. Use sensitive scope. Concurrent Logout may win first (write rejected) or mutation holds current session lock and commits first (Logout after); no user/manager acquisition from logout path. Do not trust cached FormRequest or middleware snapshot alone. Other target session deletes happen after actor binding lock; manager serialization prevents reciprocal admin mutation deadlocks; native saves/touches use session rows only.
4. Mutate explicitly mapped fields and role using native syncRoles([$role]) (skip unchanged role), validate fresh target role state, protect ID1 and invariant. Assign new avatar reference only to prepared unique file; capture old key under target lock, not stale snapshot. No new permission records/grants.
5. Reuse/extend CredentialRevocation: shared internal method changes credential generation and deletes target authoritative sessions within caller transaction, optional new Argon2id hash. Version increments only once for disable+reset; guard integer max and compare original version, exact affected row =1, no wrap. Disable from true to false always increments even if no sessions; re-enable never decrements or restores; same inactive flag/ordinary edit/eligible role replacement no increment. Other password reset increments even if same plaintext; no self-reset here. For self-disable allowed subject to invariant, clear initiating browser only after known commit; suppress post-success touch where self-revoked, native save cannot reinitialize authoritative marker. If role change removes own permission but remains eligible, success for authorized mutation then new permission next request; if last-admin fails rollback all. For delete, revoke target authority by delete sessions and user row absence, never reuse user IDs; stale native write may leave anonymous row but cannot authorize. Avoid requiring native user_id FK.
6. Run permanent role and six-essential-capabilities postcondition before commit, including custom role. All DB fields, role pivots, credential hash/version/session deletion and file reference are atomic; 409 rolls back all. Cache invalidation after transaction and known outcome, never let a cache/cleanup exception make code delete a possibly committed file. Fresh primary DB access remains authority even if cache invalidation fails; privacy-safe correlated operational error/recovery. Plan to minimally adapt mutation result/transaction boundary to expose explicit commit state for avatar coordination; test both existing callers and commit-ack fault.
7. Known success -> post-commit cleanup superseded file (§7), clear only self-revoked browser state, return minimal success. Known rollback -> staged candidate cleanup, no old deletion, no session logout unless independently invalid. Uncertain commit/disconnect -> no repeat, safe 503 where classified operational; retain candidate/old files until safe reference verification/operator reconciliation. Do not claim rollback or use blind retry. Distinguish 1205/1213 lock conflict and genuine connectivity failure from 1062/1451; bounded lock waiting proposed 5 seconds per conflicting DB lock for Users mutation, not total SLA. Restore original session timeout even on failure, discard uncertain connection and preserve original exception as F02 R05; test. No new global timeout setting.

### 7.1 Approved validation and normalization

Input file max exactly 2,097,152 bytes including allowed boundary, nonempty, actual valid upload. Single binary avatar, .png/.jpg/.jpeg/.webp matching server-detected MIME and decoded format; reject malformed, spoofing, truncated, SVG/GIF, known dual-format/polyglot/trailing-data fixtures. Use finfo plus image header/dimension inspection and bounded native GD decode, not extension/MIME alone; verify native decoder warnings/return and do not suppress failures blindly. Static avatar only, max 2048 width/height and 4,194,304 pixels, reject unsafe dimensions before decode; canonical re-encode as original accepted format (JPEG -> .jpg), strip metadata/embedded payloads, preserve aspect ratio and transparency, longest edge <=512 without enlargement, no crop; output limit 2 MiB. Bound actual decode/resize memory and execution time in isolated PHP8.2; proposed memory_limit >=128 MiB and measured peak under full Argon2id + image path (free images before password hash; avoid overlapping large allocations). Validate format structural bounds and known trailing/dual signatures; re-encode only safe pixels, never serve original bytes. No claim that generic MIME checks alone detect every possible polyglot; exact native support and rejection tests required before completion. Animated/multiframe formats and unsupported decoders fail safely; static-only/dimension/resize limits remain the approved plan. Do not install GD or change host now.

Native multipart on PHP8.2: use real POST + _method=PUT with native Laravel Request::capture method override; forbid override for other routes/methods, no extra write endpoint. JSON text update or removeAvatar uses ordinary PUT; no direct multipart PUT requirement. Verify genuine Content-Type and proper file bag, reject array/multiple/unknown file fields, file+remove true, invalid/oversize errors; safe 422 if Laravel receives invalid upload, 413 if Laravel handles whole body limit. Proposed hosting upload_max_filesize >=2M, post_max_size >=4M (bounded total fields/headers, test actual ingress), max_input_time/execution appropriate; server rejection outside Laravel separate. Test exact 2 MiB valid fixture (valid image content, not arbitrary padding), 2 MiB+1, native UPLOAD_ERR and actual method override CSRF.

**Approved parsed-file boundary (2026-11-25):** accept at most one effective scalar `avatar` from native PHP multipart parsing. Reject visible arrays, unknown/additional file fields, empty/invalid retained uploads and applicable whole-body size violations. Collapsed raw duplicate/mixed names and masked prior upload errors are outside the detection guarantee; only retained file is validated/stored. No custom multipart parser, ingress rewrite or hosting change. Actual Laravel method override and CSRF remain integration tests.

**Approved structural checks before decode:** JPEG length-aware segment walking, frame and scan structure, entropy byte stuffing and restart markers, first actual terminating EOI at EOF (not merely last two bytes); PNG signature, bounded chunks, CRC, first unique IHDR, image data and terminal IEND, static-only; WebP RIFF size, chunk lengths/padding, single static image and no animation markers/flags. Require MIME/extension/header agreement and dimension/input limits, then bounded GD decode (reject warnings/failure) and canonical re-encode; no original file storage or universal polyglot detection claim. Test the previously missed JPEG+PNG+second EOI plus baseline/progressive JPEG, malformed lengths, format bounds and real upload limits in a disposable PHP8.2 probe. Full application request PHP-managed memory and process RSS under Argon2id+image and live host capability remain later T45/deployment evidence.

### 7.2 File lifecycle / fault cases

New key is immutable, unique and never reassigned; stage validated/re-encoded file on same private disk at final key before DB mutation, check write/close/content/size; file not accessible through avatar route until DB points to it. Never remove old key during transaction. Use unique ownership constraint and reference recheck before deletion; never delete when key possibly referenced or when primary unavailable. File op and DB not one transaction. On known rollback delete candidate only if positively not referenced, leave old intact; on known commit delete superseded old key only after verifying no current reference (no reuse means cannot be newly assigned later); no file deletion for unrelated accounts. On unknown commit or post-commit cache failure keep both until positively resolved via primary authoritative state under safe serialized reconciliation; log safe request id/outcome without path or image. If cleanup fails after known commit report privacy-safe operational warning; success represents authoritative DB state, not false rollback. No queue/cron or new tracking table: document operator inventory/reconciliation with write quiescence or controlled maintenance, grace time + current DB references, backup before manual deletion and separate authorization. Crash between staging and DB write/cleanup may leave unreferenced file, never expose it. Do not allow cleanup routine to delete in-flight candidates. Test stage/write/close/DB duplicate/last admin/FK/commit ambiguity/postcommit cleanup, replacement-vs-replacement and replacement-vs-delete. No automatic deletion based on age alone.

Private read: authorized GET resolves target after capability, reads only canonical current key from primary; absent user/key => 404. Internal missing referenced file => safe 500/operational log (not masquerading as no avatar), after bounded reread if key changed during replacement/delete; if current state now absent return 404. Open/read bounded bytes before response (max2 MiB output), allow in-flight authorized read to finish on already-open immutable old version; if open loses race reread authoritative key once, never follow client path. No per-file DB locks held while streaming; ensure coherent MIME from canonical key, verify size and readable data before headers, no partial JSON/binary. Content-Type fixed image/png/jpeg/webp, Content-Disposition inline with generic safe filename if needed, Cache-Control private,no-store, X-Content-Type-Options nosniff; shared request ID, authorized credentialed same-site fetch (not assume img tag includes required Origin/Referer). Anonymous/untrusted/forbidden cannot fetch, no public/signed URL, no route to access old key. Frontend integration will need credentialed fetch + Blob URL, revoke object URL on teardown; no frontend work in F03.
